# Coordinator reporting scenarios

Use these hypothetical cases to evaluate ROUTE-007 reporting behavior against
coordination, routing, priming, review-response and watchdog guidance in source
and both rendered targets. Evaluate resulting actions and evidence consumption;
matching prose alone is not proof. Retain run results locally. No live schedule,
provider mutation or notification is needed for this evaluation.

| Case                     | Given / event                                                                                                                                            | Required outcome                                                                                                                                                                                           |
| ------------------------ | -------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Local corrections        | An authorized active owner makes three mechanical corrections and runs intermediate checks; no pending coordinator action or recorded readiness changes. | No coordinator message or acknowledgement wait. Evidence stays local and work continues.                                                                                                                   |
| Bounded recovery         | A reviewer encounters a recoverable read failure, completes authorized recovery and finishes the review.                                                 | No intermediate coordinator report. Send the completed findings once to the authorized implementation owner; retain recovery details locally.                                                              |
| Exhausted recovery       | The same recovery exhausts its supported budget and needs a missing access grant from the coordinator.                                                   | One delta names the exact grant/intervention and evidence; affected work waits, independent authorized work continues.                                                                                     |
| Actionable delta         | A dependency becomes ready with a complete local supporting report.                                                                                      | One compact provider-tagged identity/owner/head/state/action/reference delta. Resolve and validate complete route, authority, freshness and replay evidence before dispatch.                               |
| Missing evidence         | The same delta points to unreadable, stale or incomplete required evidence.                                                                              | Hold dependent action and request only the missing evidence or intervention; do not infer readiness from the summary.                                                                                      |
| Changed head             | An owner advances H to H2 while a coordinator action or recorded readiness depends on H.                                                                 | Promptly report the invalidation and invalidate dependent H evidence. Continue covered local work; revalidate H2 before action. Do not wait for completion to combine this report.                         |
| Local head               | An owner advances H to H2 during ordinary authorized work with no pending action or recorded readiness dependent on H.                                   | Keep progress local. Any later handoff carries current H2 and complete refreshed evidence; H is never reusable as H2 approval.                                                                             |
| Review handoff           | An independent reviewer has findings for a known authorized implementation owner and no distinct coordinator action.                                     | Deliver directly to that owner, without a redundant coordinator copy or lost review independence. If messaging is unauthorized, hold delivery and expose the needed authority through the authorized path. |
| Combined result          | An authorized correction is pushed, verified and its feedback disposition recorded.                                                                      | One useful coordination-relevant handoff combines the results, with full evidence referenced. No separate per-step messages; earlier required readiness invalidation remains timely.                       |
| Cross-source duplicate   | Owner delivery of event E at H succeeded for the coordinator action; watchdog then observes E/H.                                                         | Reconcile successful delivery evidence and suppress the same-action watchdog copy. Reverse source order has the same outcome.                                                                              |
| Distinct actions         | E/H requires the owner to handle feedback and the coordinator to release a dependent item.                                                               | Deliver to both authorized recipients for their distinct actions; same event/head alone must not suppress either action.                                                                                   |
| Failed delivery          | A send of E/H fails or has unknown outcome, then the watcher or owner sees E/H again.                                                                    | Keep unresolved and retryable. Refresh unknown evidence before retry; do not record success or suppress delivery from an attempt alone. Escalate only required intervention after bounded recovery.        |
| Completion               | Work reaches verified completion with no further routing needed.                                                                                         | Deliver one verified completion with evidence, then suppress successful duplicates. An unverified observation, failed delivery or prior progress notice cannot consume completion.                         |
| Explicit status          | The user requests status while work is unchanged.                                                                                                        | Answer from current evidence; quiet reporting does not hide a substantive blocker or invent readiness.                                                                                                     |
| Interrupted continuation | An owner is actually interrupted with authorized unfinished non-gate work.                                                                               | Validate existing route/provenance/source/head/acknowledged positive sequence and unfinished evidence before continuation; do not infer receipt acknowledgement from silence or bypass replay checks.      |

## Event-driven delivery and bounded reads

These cases are hypothetical. Evaluate each in source and fresh Claude/Codex
projections, retaining expected and observed actions plus evidence references.
Label evidence as contract review, simulated behavior, or actual host execution.
A source-text match is not behavioral proof. Unsupported host execution remains
unexecuted, never PASS; do not activate a schedule or alter a live batch to test.

| Case                     | Given / event                                                                                                                          | Required outcome                                                                                                                                                                                                                                                                                   |
| ------------------------ | -------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Yield, gate, wake, route | Coordinator yields after dispatch. Known owner O reaches a publication gate at H and sends through the verified reporting path.        | O holds publication and may continue independent covered work. Supported delivery wakes the coordinator; it resolves the full report, validates current route/authority/O/H and gate evidence, routes only the authorized next action, then yields. Delivery alone does not authorize publication. |
| Progress polling         | No owner report arrives; coordinator repeats owner reads, snapshots or waits to discover whether work advanced or a gate appeared.     | Prohibited even at longer intervals or through differently named tools. Yield for reports; do not install a polling fallback.                                                                                                                                                                      |
| Initial binding          | A supported create result identifies exact O/host; release requires O's initial waiting state.                                         | One bounded purpose-specific observation confirms identity/state or names the unknown fact. Stop there; after release await the delivered handoff rather than looping for progress. Creation/sent binding is not readiness.                                                                        |
| Received report          | Delivered report points to current evidence at H, or its reference is unavailable/stale at H2.                                         | Resolve and validate before action, ending at success or the specific evidence gap. Old-head or inaccessible evidence holds only the dependent action; do not watch O for a replacement report.                                                                                                    |
| Status read              | Human asks for current O status.                                                                                                       | Bounded supported read answers from current facts and ends; no unattended status loop follows.                                                                                                                                                                                                     |
| Uncertain operation      | A specific send/creation outcome is unknown.                                                                                           | Reconcile that operation's supported result under existing recovery budget; stop at established result or exhausted recovery gap. Never broaden into ordinary-progress observation, blind resend, replacement creation, or invented success.                                                       |
| Recipient evidence gap   | Human authorization is visible to coordinator but inaccessible to O, including approval in an ephemeral side conversation.             | Before unattended release, expose missing recipient-visible human evidence and obtain only that instruction through a supported surface. Forwarded agent claims/copies cannot fabricate consent. No polling fallback.                                                                              |
| Missing transport        | Identities and human authority are valid but host cannot send/wake the coordinator.                                                    | Expose the actual supported transport limitation before claiming unattended continuation. Do not treat chat creation as return transport or substitute owner-progress polling.                                                                                                                     |
| Retained authority       | O validated actual human reporting permission for coordinator C; routine gate/head changes or compatible resume follow.                | Retain recipient/host/scope/evidence and reuse authority without repeated human approval. Refresh action evidence for new heads. Revocation, uncovered recipient/effect, unverifiable evidence or an actual host requirement holds only the affected message/action.                               |
| Job completion           | O's accepted job is verified complete and a supported completion send succeeds; unrelated batch work remains.                          | Deliver one current-head completion report with route/owner/evidence, needing no routine acknowledgement. Suppress successful duplicates; coordinator separately validates batch obligations. Unknown/failed delivery cannot consume completion.                                                   |
| External watchdog        | External issue/PR feedback requires O action; no coordinator intervention is needed.                                                   | Notify known authorized O without polling its job. Preserve distinct-action controller exceptions, existing event/head deduplication, bounded recovery and prompt readiness invalidation.                                                                                                          |
| Satisfied covered gate   | Publication, conditional merge, or cleanup conditions pass with retained standing authority; current head/action binding is refreshed. | Advance through the existing effect owner without a repeated human permission request. Report only a distinct routing need or verified result; missing/revoked authority, expansion, unresolved choice, gate exception or actual host restriction remains actionable.                              |
