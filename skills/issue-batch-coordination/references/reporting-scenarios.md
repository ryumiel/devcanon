# Coordinator reporting scenarios

Use these hypothetical cases to evaluate ROUTE-007 reporting behavior against
coordination, routing, priming, review-response and watchdog guidance in source
and both rendered targets. Evaluate resulting actions and evidence consumption;
matching prose alone is not proof. Retain run results locally. No live schedule,
provider mutation or notification is needed for this evaluation.

| Case                     | Given / event                                                                                                                                            | Required outcome                                                                                                                                                                                           |
| ------------------------ | -------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Local corrections        | An authorized active owner makes three mechanical corrections and runs intermediate checks; no pending coordinator action or recorded readiness changes. | No coordinator message or acknowledgement wait. Evidence stays local and work continues.                                                                                                                   |
| Bounded recovery         | A reviewer encounters a recoverable read failure, completes authorized recovery and finishes the review.                                                 | No intermediate coordinator report. Send the completed findings once to the authorized implementation owner; retain recovery details locally.                                                              |
| Exhausted recovery       | The same recovery exhausts its supported budget and needs a missing access grant from the coordinator.                                                   | One delta names the exact grant/intervention and evidence; affected work waits, independent authorized work continues.                                                                                     |
| Actionable delta         | A dependency becomes ready with a complete local supporting report.                                                                                      | One compact provider-tagged identity/owner/head/state/action/reference delta. Resolve and validate complete route, authority, freshness and replay evidence before dispatch.                               |
| Missing evidence         | The same delta points to unreadable, stale or incomplete required evidence.                                                                              | Hold dependent action and request only the missing evidence or intervention; do not infer readiness from the summary.                                                                                      |
| Changed head             | An owner advances H to H2 while a coordinator action or recorded readiness depends on H.                                                                 | Promptly report the invalidation and invalidate dependent H evidence. Continue covered local work; revalidate H2 before action. Do not wait for completion to combine this report.                         |
| Local head               | An owner advances H to H2 during ordinary authorized work with no pending action or recorded readiness dependent on H.                                   | Keep progress local. Any later handoff carries current H2 and complete refreshed evidence; H is never reusable as H2 approval.                                                                             |
| Review handoff           | An independent reviewer has findings for a known authorized implementation owner and no distinct coordinator action.                                     | Deliver directly to that owner, without a redundant coordinator copy or lost review independence. If messaging is unauthorized, hold delivery and expose the needed authority through the authorized path. |
| Combined result          | An authorized correction is pushed, verified and its feedback disposition recorded.                                                                      | One useful coordination-relevant handoff combines the results, with full evidence referenced. No separate per-step messages; earlier required readiness invalidation remains timely.                       |
| Cross-source duplicate   | Owner delivery of event E at H succeeded for the coordinator action; watchdog then observes E/H.                                                         | Reconcile successful delivery evidence and suppress the same-action watchdog copy. Reverse source order has the same outcome.                                                                              |
| Distinct actions         | E/H requires the owner to handle feedback and the coordinator to release a dependent item.                                                               | Deliver to both authorized recipients for their distinct actions; same event/head alone must not suppress either action.                                                                                   |
| Failed delivery          | A send of E/H fails or has unknown outcome, then the watcher or owner sees E/H again.                                                                    | Keep unresolved and retryable. Refresh unknown evidence before retry; do not record success or suppress delivery from an attempt alone. Escalate only required intervention after bounded recovery.        |
| Completion               | Work reaches verified completion with no further routing needed.                                                                                         | Deliver one verified completion with evidence, then suppress successful duplicates. An unverified observation, failed delivery or prior progress notice cannot consume completion.                         |
| Explicit status          | The user requests status while work is unchanged.                                                                                                        | Answer from current evidence; quiet reporting does not hide a substantive blocker or invent readiness.                                                                                                     |
| Interrupted continuation | An owner is actually interrupted with authorized unfinished non-gate work.                                                                               | Validate existing route/provenance/source/head/acknowledged positive sequence and unfinished evidence before continuation; do not infer receipt acknowledgement from silence or bypass replay checks.      |

## Execution startup scenarios

Evaluate these startup decisions with the reporting cases above; timer ticks
observe external events and never periodically discover owner progress. These
are hypothetical method evaluations, not live scheduled-delivery evidence.

| Case                       | Given / event                                                                                                                                              | Required outcome                                                                                                                                                                                                                                                        |
| -------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Fresh execution            | A concrete accepted batch needs new owners and has no monitor; supported controls and verifiable human authorization cover every setup effect and cadence. | Invoke eligible new owners with `--auto`, create one efficient-tier watchdog and its timer, bind actual recipients, and verify owner/task/model/timer/notification facts separately. No repeated approval question.                                                     |
| Inspection                 | The user requests status with no execution instruction.                                                                                                    | Read and report current evidence; zero task creation, messages, priming or scheduling effects.                                                                                                                                                                          |
| Independent overrides      | The user chooses interactive owners while monitoring remains requested, or autonomous owners with no monitoring.                                           | Apply each choice only to its component. Never silently change already-bound owner mode.                                                                                                                                                                                |
| No-monitor startup         | Autonomous owners are accepted with no-monitor; no monitor model/cadence preference or monitor-specific permission is available.                           | Select owner work first and continue covered `--auto` owners. Zero watcher creation, monitor-specific messaging authorization, capability/model/cadence inquiries or activation; absent monitor requirements are not failed gates.                                      |
| Retained stop on resume    | A prior explicit monitor stop remains effective; generic resume accepts owner continuation with an already-bound interactive or autonomous mode.           | Preserve stop and owner mode; continue independently covered owners. Zero watcher creation, monitor-specific messaging authorization, capability/model/cadence inquiries or activation. Generic resume cannot supply scheduling authority.                              |
| Explicit active-timer stop | The user explicitly requests stopping an existing active timer while selecting no new monitoring.                                                          | Select only bounded shutdown; check necessary host control/permission and verify observed stop. Preserve unknown outcome for reconciliation; no replacement, monitor messaging/model/cadence inquiry or competing activation. Independent covered owner work continues. |
| Existing decisions         | A resumed batch has valid human setup authorization and compatible owner/watchdog settings.                                                                | Reuse evidence and bindings without generic reapproval; preserve user/saved cadence and independent effort/model overrides. Create only missing authorized components.                                                                                                  |
| Partial permission         | Monitoring is selected and creation is covered but a host requires direct human authorization for one messaging direction or timer activation.             | One bounded request identifies only uncovered effects, roles/directions/cadence and actual host restrictions; hold those effects and continue independent covered work. Separately scoped delivery decisions are collected only if missing; no silent expansion.        |
| Recipient evidence         | The controller's asserted authorization is copied into an owner prompt but the actual human decision cannot be verified.                                   | Hold dependent unattended messaging and name one concrete missing-evidence action. Arrange a direct recipient-conversation human step only if that host requires it; do not infer refusal.                                                                              |
| Cadence and effort         | Monitoring is enabled and no user/saved cadence exists; a supported configured host cadence exists, or none exists.                                        | Use that configured default, otherwise request cadence before activation. Use independent user effort or host default; efficient model supplies neither interval nor effort.                                                                                            |
| Unavailable controls       | Monitoring is selected but task creation, efficient model setting, timer targeting or messaging is unsupported/rejected.                                   | Expose the exact affected limitation; no ambient model, custom scheduler or implicit heartbeat fallback. Authorized owner work continues.                                                                                                                               |
| Partial or unknown startup | Watchdog creation succeeded but timer activation failed/has unknown outcome; or task creation is pending.                                                  | Retain identities/outcomes in existing monitor state and reconcile before retry. Do not create a duplicate task or competing active timer or claim monitored operation.                                                                                                 |
| Reuse and switch           | A compatible watchdog/timer exists; later an explicit monitoring-mode switch is authorized.                                                                | Reuse without duplicate activation. Verify predecessor timer stop before competing activation; unknown stop holds switch.                                                                                                                                               |
| Failed event delivery      | Timer observes external E/H for a known owner but delivery fails.                                                                                          | Retain unresolved retryable delivery; unchanged successful events are quiet. Escalate only an actionable exhausted recovery to the coordinator.                                                                                                                         |
| Explicit stop              | A stopped monitor encounters a generic resume.                                                                                                             | Preserve stop; no automatic recreation. Later explicit scheduling authority may supersede it after verified one-mode checks.                                                                                                                                            |
| Successor                  | An authorized new controller adopts the batch.                                                                                                             | Preserve notification state and recipient authority, acknowledge handoff, verify supported timer retargeting or predecessor retirement before replacement.                                                                                                              |
| Terminal shutdown          | The controller verifies every accepted item and authorized post-merge obligation complete.                                                                 | Stop/pause timer through its host control and verify the result separately from archival. Unsupported stop remains unresolved.                                                                                                                                          |
| Explicit heartbeat         | The user selects a supported authorized coordinator heartbeat.                                                                                             | Keep one active mode; bounded event/recovery work only, with no periodic owner-progress discovery.                                                                                                                                                                      |

| Initial PR publication            | Implementation and validation pass, independent Phase 7 branch review passes, and exact publication authority is current.            | Publish the initial PR through the existing owner only after those gates; report the reviewed current PR/head for downstream routing.                                                                                                                                                                                                                                                                   |

Refresh exact H2 bindings and genuine feedback/CI/protection/mergeability gates; no generic human reapproval. |

| Conditional delivery and cleanup  | Current-head genuine merge gates pass; accepted dependency work still needs this worktree after merge.                               | Route exact merge through pr-merge under retained authority; preserve dependent resources/evidence/ledger. Cleanup and terminal timer shutdown wait for outstanding accepted obligations.                                                                                                                                                                                                               |
