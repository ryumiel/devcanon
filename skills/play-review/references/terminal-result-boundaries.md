# Terminal-result boundaries — `play-review`

Load this reference when interpreting the ownership boundary for Phase 3 terminal role results. `SKILL.md` remains the eager owner of the dispositions, capture-before-cleanup sequence, diagnostic split, and critic gate.

| Boundary | Preserved responsibility                                       |
| -------- | -------------------------------------------------------------- |
| B1       | Child result return and validation remain controller-captured. |
| B2       | Lifecycle capture remains before cleanup or supersession.      |
| B3       | Terminal D7 completion remains the gate to critic eligibility. |
| B4       | Source-to-rendered target representation remains derived.      |

## Routine recovery

Authorization to review includes routine correction within that scope. Do not ask
for new approval merely because a result was rejected. Explicit user stop or
attempt limits still prevail. Rejection prevents consumption of that result; it
does not permanently prohibit reviewing the unchanged candidate.

After successful guard verification and exact cleanup, use the following recovery:

| Failure                                                         | Action                                                                                                                                |
| --------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------- |
| Redundant presentation only                                     | Derive `body` from valid canonical fields through the findings helper; no new review needed.                                          |
| Malformed semantic field                                        | Ask the same reviewer to correct the named field from source and return a complete replacement; do not suggest the desired judgment.  |
| Missing coverage or context                                     | Supply available in-scope source and ask the same reviewer to complete the named checks. Missing coverage still blocks approval.      |
| Incorrect D18 context                                           | Discard it and allow one fresh independent D18 preparation from the frozen source inputs; never pass the rejected summary as context. |
| Tool or transport interruption                                  | Resume the same reviewer where supported. If unavailable, use a fresh independent replacement with the same route and required scope. |
| Source mutation, guard verification failure, or cleanup failure | Stop immediately after the required cleanup attempt. Preserve the incident; never reset source or retry around it.                    |

Allow one corrective continuation per D7/D10 route and one fresh D18 preparation
attempt per frozen candidate under the current authorization. Keep that count in
existing owner continuation state across resumes or new invocations; an unavailable
reviewer's replacement consumes the same correction allowance. A repeated failure
or unavailable required input ends incomplete with the concrete reason. Human
input is needed for a scope/authority exception or a further attempt after exhaustion,
not the routine correction itself. Native dispatch rejection and model-capacity
failures retain the dispatch ritual and lifecycle owner's restrictions; this
policy cannot authorize a prohibited retry, substitute role, or changed model.
Do not retry completed substantive judgments or
allocate another reviewer to obtain a preferred verdict. D10 correction remains
limited to the originally selected claims.

Capture a fresh guard before each continuation or replacement, then verify,
validate, and clean before consumption using the normal lifecycle protocol.
Preserve the original attempt diagnostically; the reviewer returns a full result
including coverage and all claims, not a patch the controller merges into approval.
No rejected findings or incomplete coverage become accepted by subtraction.

For D7/D10 correction within the same candidate, accepted context may remain in
use only after checking the exact repository, base/head/tree, active/full ranges,
frozen source and policy inputs, artifact digests, and live custody association.
Changed or uncertain inputs invalidate reuse: return to normal preparation and
scope selection. A digest or integrity failure stops; it is not ordinary staleness.
Never reuse rejected D18 context. A new invocation alone neither resets the retry
allowance nor makes rejected evidence valid. A genuinely changed candidate needs
fresh applicable review and cannot inherit approval.
